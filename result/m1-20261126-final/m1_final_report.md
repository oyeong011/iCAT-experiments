- **측정 범위**
  - VmallocUsed는 시스템 전체 vmalloc 페이지 수이다. 모듈 이미지가 들어가고, 예약된 8 GiB 에뮬레이션 메모리(memmap)는 들어가지 않는다.
  - /proc/vmallocinfo는 root 전용이라 할당 하나하나를 볼 수 없다.
  - 그래서 정책 비용은 두 run의 증가량 차이(⑤)로 본다.
- **할당과 해제 시점**
  - 모든 항목은 모듈을 적재할 때 할당된다(`conv_init_ftl`, `init_lines`, `smartgc_init`).
  - 모듈을 제거할 때 `conv_remove_namespace`가 해제한다.
  - 실행 중 증가량(⑥)이 적재 직후와 같으므로 실행 중 추가 할당은 보이지 않는다.
- **공통 메모리**
  - maptbl과 rmap은 32 MiB [계산]이고 두 정책이 같다.
  - SUnreclaim이 약 104 MB 늘었다 [측정]. 두 정책이 같고, ssd.c가 페이지마다 kvmalloc하는 NAND 상태 배열로 보인다.
  - 이 둘은 NVMeVirt 공통 메모리이며 정책 비용으로 계산하지 않는다.
- **판정 근거**
  - 정책 간 실측 차이 2,904 kB는 계산 차이 3,058 kB와 −5 % 차이다.
  - 측정 잡음(SD 약 54 kB)보다 훨씬 크다.
  - 실측 차이는 ①+②+③의 합에 해당한다. ①만 따로 잰 실측값은 없다.

### 3.2 CPU 시간

- **커널 안 실제 CPU 시간: 측정 불가.** 이유는 세 가지다.
  - 이 커널에 맞는 perf가 없다.
  - nvmev 스레드가 busy-poll이라 /proc/stat에서 CPU 1·2가 모든 정책에서 100 %로 나온다.
  - sum_exec_runtime은 µs 단위 구간을 잴 만큼 해상도가 없다.
- 커널 경과 시간을 CPU 시간으로 바꿔 적지 않는다.
- **대체 측정**: 사용자 공간 벤치마크 (`userspace_cpu_time.csv`, 별도 표, 커널 값과 직접 비교하지 않음)
  - 같은 conv_ftl.c를 사용자 공간 드라이버로 돌렸다.
  - 부하: zones 합성 부하, 8 GiB × 6배 덮어쓰기. **mixY가 아니다.** seed 3개.

- 이 합성 부하에서도 GC와 선택 비용은 iCAT이 크다. 방향은 커널 결과와 같다.
- 한편 이 부하에서 iCAT 학습기는 판단 구간을 한 번도 끝내지 않았다(windows=0). 그래서 학습기 결정 비용은 이 표에 들어 있지 않다.

## 5. 부족한 항목과 해결 방법 (추가 실험은 시작하지 않음)

| 부족 | 해결 방법 | 예상 비용 |
|---|---|---|
| 독립 반복 (n=1) | 취소한 4회를 새 사전 등록으로 실행 | 고컴 약 40 h (10 h × 4) |
| 커널 CPU 시간 | perf나 커널에 맞는 bpftrace를 설치하고, `task_clock`이나 구간별 `local_clock` 기반 계측 빌드를 만든다. busy-poll 스레드에서도 구간 CPU 시간은 경과 시간과 거의 같을 것으로 예상하나 확인되지 않았다 | 빌드와 검증 약 4 h, 본 실행 정책당 10 h |
