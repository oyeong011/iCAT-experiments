# 승컴 최종 리비전 자료 패키지 (2026-11-27)

집컴이 `iCAT_Revision_Final.xlsx`를 만들 때 쓸 승컴 몫이에요. 새 실험은 하지 않았고, 원시 로그도 고치지 않았어요.

- 생성: `python3 -I -B analysis/revision/seungcom_package.py`
- WAF 통계의 출처는 `result/final-validation-20261127/final_statistical_validation.csv`예요. 원시 로그에서 다시 계산한 값이고, 고컴 Excel·집컴 자료와 불일치가 0이었어요.
- 부하는 모두 mixFYF 90분이에요 (FIO 1800 s → YCSB-A 250k 1800 s → FIO 1800 s). 호스트는 승컴 i7-7700이고, 정책당 n=3이에요.
- 오차 막대와 CI는 모두 **95 % CI**예요 (t 분포, df=2).
- 각 변형은 **자기 배치의 iCAT-v4와만** 비교했어요.

## 1. Figure 1 — Greedy GC (승컴 몫)

| Experiment | Baseline WAF (95 % CI) | iCAT WAF (95 % CI) | Improvement (%) | Holm p |
|---|---|---|---|---|
| Greedy GC | 2.629 [2.612, 2.647] | 2.110 [2.050, 2.171] | **19.7** | 0.0013 |

- Improvement = (Baseline − iCAT) / Baseline × 100이에요. "V4 대비 +24.6 %"(= 차이 / iCAT)와 기준이 달라서, 엑셀에는 정의를 같이 적어야 해요.
- iCAT 값은 같은 큐에서 번갈아 돌린 batchG의 V4예요. 같은 seed를 썼어요.
- Greedy GC는 WAF는 나쁘지만, FIO 쓰기 p99 지연은 더 낮았어요 (단계 C −124 µs).
- **W1~W4:** 승컴의 Greedy GC vs iCAT-v4 비교는 mixFYF 하나뿐이에요.
  - 9월 9개 부하 비교(mix-20260911)는 원래 iCAT(online)과 9월 Greedy 모듈을 비교한 것이에요. 코드 버전이 달라서 V4 그래프에 넣으면 안 돼요.
  - mixFYF 값을 W1~W4에 대입하지 않았어요.

## 2. Table 1 — Ablation (승컴 변형, 소스 확인)

소스는 `revD-src`예요 (`sources.sha256` 검사 통과). 변형은 `ICAT_VARIANT`나 `ICAT_EXTRA` 플래그로만 갈라져요. 각 칸은 변형 이름이 아니라 `conv_ftl.c`의 분기 조건을 읽고 채웠어요.

- Holm 가족은 배치별로 2개 대비 × {전체, 단계 C} = 4예요. CI가 있는 건 절대 Δ뿐이에요 (`ablation_table.csv`). 정규화 WAF는 평균의 비율이고 CI는 없어요.
- **코드 근거** (`revD-src/conv_ftl.c`)
  - **할인:** 317–321, 584–586행이에요. γ_Q16 = 65536이면 `(v>>16)*65536 + ((v&0xFFFF)*65536>>16) = v`가 돼서 할인이 항등이 돼요. 그래서 NoDiscount는 "할인 없음"이 맞아요.
  - **후보 제거:** 620–636행이에요. VARIANT 2, 3에서 꺼져요.
  - **정착:** 540–551행이에요. VARIANT 2, 5, 9에서 꺼져요.
  - **변화 감지:** 567–579행이에요. VARIANT 1에서 꺼지고, `settled`일 때만 작동해요.
  - **리셋 범위:** 486–490행이에요. VARIANT 7이면 `WATGC_V2_ALLOWED`(45개 전부)로 되돌리고, 나머지는 `watgc_v2_grow`(살아남은 후보 + 이웃)를 써요.
  - **probe:** 637–657행이에요. 정착한 뒤에만 이 코드에 도달해요.
- **템플릿 행과 다른 점**
  - OffBundle은 템플릿의 "NoElim+NoSettle"과 같지 않아요. 정착이 없으면 변화 감지와 probe도 구조적으로 꺼져서, 네 가지가 함께 빠진 변형이에요.
  - 그래서 Probe 열을 추가했어요. 이 행은 개별 기능의 효과가 아니라 묶음의 효과예요.
  - 템플릿의 "NoElim"(고컴 revE)과 "NoElim+NoSettle"(고컴 revB)은 고컴 자료예요.
- **고컴 확인 요청**
  - revD-src에서 VARIANT 5는 "정착 안 함"이에요. 정착이 없으면 변화 감지와 probe도 같이 꺼져요.
  - 고컴 revB-nosettle 등이 VARIANT 5라면, 그 행도 Drift ✗, Probe ✗로 적어야 해요.
  - 고컴 빌드 플래그로 확인해 주세요. 승컴은 고컴 행을 채우지 않았어요.
- **실행 모듈 검증** (`module_verification.csv`)
  - 기록된 플래그로 revD-src를 다시 빌드했어요. 정규화한 objdump가 실제 실행 모듈과 **7개 모두 0줄 차이**였어요.
  - 이 검사가 실제로 차이를 잡아내는지 음성 대조로 확인했어요.
    - 상수 하나만 다른 경우: drift50 vs V4는 2줄 (`shl $0xf` vs `$0xe`, 즉 50 % vs 25 % 문턱), NoDiscount vs V4는 48줄이었어요.
    - 분기가 다른 경우: 404–3,023줄이었어요.
  - Greedy GC 모듈도 revD-src를 `NVMEVIRT_GC_POLICY=GREEDY`로 빌드한 것과 같았어요.

## 3. 파라미터 민감도 (승컴)

| 파라미터 | 기본값 (소스) | 승컴 실험 | 결과 |
|---|---|---|---|
| 할인율 γ | **0.99949646** (Q16 65503). 0.99가 아니에요 | γ = 1.0 (NoDiscount)뿐이에요 | −0.004, Holm p 1. 0.90, 0.95, 0.99는 **미실험**이에요. 끝점이 하나뿐이라 곡선을 그릴 수 없어요 |
| 탐색 계수 C | 0.25 (WAF 단위 UCB 보너스) | **없음** | 모든 소스 트리(online-*, revD-src)에서 16384로 고정이에요. **미실험** |
| 후보 제거 문턱 | 15 % | 15 %만 | 10 %, 25 %는 고컴 revC 자료예요 |
| 변화 감지 문턱 | 25 %, 3구간 연속 | **50 %** (drift50, batchG 같은 큐) | +0.018 [−0.045, +0.081], Holm p 0.83, 차이 확인 못 함. 12.5 %는 고컴 revE 자료예요 |

- drift50은 기능을 뺀 게 아니라 문턱만 바꾼 실험이라 **Parameter Sensitivity**에 넣어야 해요.
- V4 리셋의 편차가 모두 50 %를 넘었어요. 그래서 이 부하에서는 25 %와 50 %가 다르게 동작할 기회가 거의 없었어요.
- 어느 설정도 "최적"이라고 주장할 근거가 없어요.

## 4. 학습기 지표 (기존 kernel.log에서 추출, 기술 통계만)

- 계산 방법
  - 측정 시작 init 뒤의 `WATGC_V2 summary`, `settled`, `reset`, `sample` 줄을 썼어요.
  - 파티션 4개를 평균해 실행 하나의 값으로 만들고, 그 값을 실행 3개에 대해 평균했어요.
  - 이 지표에는 검정을 하지 않았어요.
- 기존 ablation 보고서와 대조했어요. 선택 변경 횟수가 abl-v4 569회, OffBundle 867회로 같아요.

| 정책 | 정착한 파티션 | 첫 정착까지 (s) | 첫 정착 때 남은 후보 (45개 중) | 정착 전 탐색 구간 | 전체 탐색 구간 (probe 포함) | 리셋 수 / 실행 | 리셋 후 재정착까지 (구간 / s) |
|---|---|---|---|---|---|---|---|
| revD-v4 | 4/4 | 1,741 | 16.0 | 84.7 | 131.8 | 4.0 | 27.8 / 650 |
| NoDrift | 4/4 | 1,932 | 13.7 | 79.9 | 125.7 | 0 | 해당 없음 |
| FullReset | 4/4 | 2,339 | 10.8 | 87.3 | 165.2 | 4.0 | **66.6 / 1,266** |
| abl-v4 | 4/4 | 1,748 | 17.7 | 79.9 | 124.2 | 4.0 | 19.2 / 394 |
| NoDiscount | 4/4 | 1,713 | 15.1 | 78.2 | 129.8 | 4.0 | 21.7 / 448 |
| OffBundle | **0/4** | 정착 없음 | 해당 없음 | 해당 없음 | 199.5 | 0 | 해당 없음 |
| bg-v4 | 4/4 | 1,855 | 13.2 | 77.5 | 128.7 | 4.0 | 18.3 / 282 |
| drift50 | 4/4 | 1,953 | 14.3 | 82.9 | 124.2 | 3.7 | 20.1 / 317 |

- **후보 제거 문턱과 실제 제거 비율은 달라요.** 문턱은 15 %인데, 첫 정착 때 남은 후보는 45개 중 11–18개였어요. 즉 61–76 %가 제거됐어요.
  - `elim` 카운터는 제거 "횟수"예요. probe나 리셋으로 되살아난 후보가 다시 제거되면 또 세요. 그래서 이 값을 45로 나눠 비율로 쓰면 안 돼요.
- **FullReset은 리셋 뒤 다시 정착하기까지 V4보다 약 2.4배 오래 걸렸어요.** 66.6구간 대 27.8구간, 같은 revD 배치예요.
  - 리셋 때 후보 45개를 전부 되살리기 때문이에요.
  - 이 지표는 기술 통계라서 유의성은 주장하지 않아요.
- 재정착하지 못한 리셋(관측 중단)은 0건이에요.

## 5. 비교할 수 없는 것과 그 이유
