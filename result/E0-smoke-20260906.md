# NVMeVirt E0 계측 smoke 실행

2026-09-06, kernel 7.0.0-30-generic. 기존 소스의 Greedy 정책을 새로 빌드하여 실행했다. 정책 소스 변경 없음.

## 실행 조건

- 모듈: `buildoutput/nvmev-e0-greedy-20260906.ko` (인접 build-info 파일에 SHA256 기록)
- 예약 메모리: `memmap=8G$4G`, 모듈 CPU: `1,2`
- 새 가상 장치: `/dev/nvme0n1`, model `CSL_Virt_MN_01`, 약 7.5 GiB 논리 용량
- 각 실행마다 새 ext4와 6 GiB preset. 실행 전 NVMe namespace와 대상 mount가 없음을 확인했다. 물리 SATA 디스크는 사용하지 않았다.
- 기존 `test3.fio`: 4 KiB direct random writes, hot/warm/cold = 6000/3000/1000 IOPS, 기존 고정 seed 사용.
- 실행 명령: `FIO_RUNTIME=60 bash script/run.sh e0-greedy-20260906 test3 1`, 이어서 `FIO_RUNTIME=120 bash script/run.sh e0-greedy-20260906 test3 2`.
- 두 실행은 길이가 다르므로 반복성 검증용 paired repeats가 아니다.

| 실행 | 측정 host pages | 측정 GC copy pages | GC count | 재계산 WAF | 로그 WAF |

| 120초 | 725723 | 342531 | 16683 | 1.471985868 | 1.471 |

120초 실행의 두 완결 window도 각각 1.273918152, 1.558547974로 재계산했으며 로그의 소수 셋째 자리 버림 값 1.273, 1.558과 일치했다. 마지막 미완결 window는 별도 window 로그로 출력되지 않는다.

120초 fio 결과: 1200000 write I/O, 9999 IOPS, 39.1 MiB/s, 평균 total latency 20.75 us, p99 completion latency 59 us. IOPS는 workload에서 제한한 값이므로 장치 최대 성능이 아니다. preset과 본 실행 모두 fio err=0, 스크립트 exit=0. 저장 로그에서 BUG/Oops/WARNING/error 패턴은 발견하지 못했다. 종료 후 가상 namespace와 mount가 제거됨을 확인했다.

## 판정과 남은 검증

계측 smoke 실행과 출력 WAF의 산술 일치만 확인했다. E0 전체 통과가 아니다.

현재 host/GC 카운터는 각 FTL partition의 첫 GC가 완료된 이후에 활성화되므로 전체 실행 쓰기량이 아니다. fio 전체 쓰기량과 직접 비교하면 안 된다. 독립 NAND write 카운터와의 대조, 공통 측정 시작 경계, 고정 iCAT 등가성, reward 전달 검증, 동일 조건 반복성은 아직 검증하지 않았다. 온라인 학습기와 전체 parameter sweep도 이번에 실행하지 않았다.

빌드는 성공했으나 compiler 명칭 차이, pahole 차이, MODULE_DESCRIPTION 누락, vmlinux 부재에 따른 BTF 생략 경고가 있었다.
