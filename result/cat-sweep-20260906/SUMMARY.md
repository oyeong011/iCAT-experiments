# CAT 설정 sweep 결과

집계일: 2026-09-07. 신규 87회와 baseline test3 CAT 3회를 합쳐 30조건 × 3회 = 90개 관측을 집계했다. 각 run의 원시 host/GC 카운터에서 `1 + GC/host`를 재계산하고 run별 WAF를 산술 평균했다. 조건당 동일 seed 3회이며 multi-seed 실험이 아니다.

실험 질문: CAT 설정에 따라 WAF가 달라지는가, test2/test3에서 좋은 설정이 달라지는가? 모든 실행은 static CAT이며 학습·온라인 전환·phase 변화는 없다. scale 5개 × ratio 3개를 평가했고 Age 구간 수는 7로 고정했다.

- test2: 1 GiB hot 8000 IOPS + 5 GiB cold 2000 IOPS.
- test3: 512 MiB hot 6000 + 1.5 GiB warm 3000 + 4 GiB cold 1000 IOPS.
- 각 run: 새 가상 SSD/ext4, 6 GiB preset, direct 4 KiB random write 600초. CREATE Age, 기존 GC/계측 정의 유지.
- scale은 Age 구간 시간 경계의 배율(%), ratio는 Age 가중치 최대/최소 비율이다.

평균 최저 설정은 workload별로 다르다. 다만 test3의 (100,16)은 1.803874로 (200,7)과 매우 가깝고 반복 범위도 겹친다. 현재 결과만으로 유일한 최적 설정이나 통계적 우월성을 확정하지 않는다. 동일 데이터에서 가장 낮은 평균을 선택했으므로 선택 편향이 있으며 별도 검증 입력이 필요하다.

## 검증과 한계

- 신규 87회 모두 batch 기록상 exit=0, fio err=0, 각 본 workload 6,000,000 writes. 전체 90개 로그에서 양수 host 카운터 및 출력 WAF의 소수 셋째 자리 버림과 재계산값 일치 확인.
- 계획된 조건별 관측 3개씩 확인했다. 신규 계획은 [plan.tsv](plan.tsv), 재사용 3건은 상위 [실험일지](../../EXPERIMENT_LOG.md)에 연결돼 있다.
- 완료 후 namespace 없음 및 mount 해제 확인. 환경 snapshot 전체 항목의 자동 대조나 독립 NAND 계측 검증은 수행하지 않았다.
- WAF는 각 FTL 첫 GC 이후부터 teardown까지 집계한 값이다. 전체 application write amplification과 다르며 정책마다 완전히 같은 입력 구간을 평가한 것이 아니다.
- test3 (100,7)은 앞선 baseline batch를 재사용했다. 모듈 byte 및 소스/workload 일치를 확인했지만 시간대와 background 부하 차이는 배제하지 못한다.
- CPU 주파수/부하와 concurrent job interleaving은 통제되지 않았다. 실제 NAND erase 지연 0 및 early completion 등 기존 모델 설정의 한계도 유지된다.
- 이번 결과는 static parameter 민감도의 관측이다. 온라인 적응 필요성, phase별 optimum 이동, iCAT 효과, Q-learning 필요성을 입증하지 않는다. 95% CI나 유의성 검정은 이번 기초 집계에서 산출하지 않았다.
