# 판단 구간 민감도 실행 계획 (제출용, 승인 전 실행하지 않음) — 고컴, 2026-11-25

## 1. 현재 값과 근거

| 상수 | 값 | 위치 (revC-src) | 근거 |
|---|---|---|---|
| `WATGC_V2_WINDOW_HOST_PAGES` | 131,072 페이지 = 512 MiB | `conv_ftl.h:52–53` | v3에서 v1(256 MiB)의 2배로 키웠다. 측정 비교는 없다 |
| `WATGC_V2_WINDOW_GC` | 128회 | `conv_ftl.h:49–50` | 같다 (v1 64회의 2배) |
| `WATGC_V2_MAX_WINDOW_GC` / `_NS` | 8,192회 / 300 s | `conv_ftl.h:56–57` | 상한을 넘은 창은 버린다 (undersized) |
| 창 끝 조건 | host 512 MiB **그리고** GC 128회 | `conv_ftl.c` `on_gc` | — |

- 실측 창 수 (고컴 revA-v4 mixFYF, 4 파티션 합, 3회):
  - 단계 B(YCSB-A) 43–44개 → 파티션당 1800 s에 약 11개, **창 하나에 약 164 s**
  - 단계 C(FIO-Fast) 508–509개 → 창 하나에 약 14 s
  - 버린 창은 0개다.

## 2. 구현 가능성

- 두 상수는 revC-src에서 `#ifndef`로 감싸져 있다. `ICAT_EXTRA`로 빌드만 하면 된다 (drift12와 같은 방식, 기계어 차이 확인 포함). 코드 수정은 필요 없다.
- **위험 1 (1 GiB 수준):** 단계 B의 창이 약 328 s로 늘어 300 s 상한을 넘는다.
  - 그러면 단계 B 관측이 대부분 버려진다. 이것은 창 크기 효과와 상한 효과가 섞인 결과다.
  - 대안 A: 상한(`MAX_WINDOW_NS`)도 같은 비율로 600 s로 늘린다. 이 상수는 `#ifndef`로 감싸져 있지 않아 헤더 1줄 수정이 필요하다.
  - 대안 B: 상한은 그대로 두고 "버린 창 수"를 결과로 보고한다.
  - **권장은 A**다. 상수 둘을 같이 바꾸는 것이므로 사전 등록에 명시한다.
- **위험 2:** 창 수로 정의된 상수(STABLE 12, STALE 240, PROBE 8, DRIFT 3창, γ 반감기 1,376창)의 실제 시간 길이가 창 크기에 비례해 바뀐다.
  - 이것은 "판단 구간" 설계 자체의 일부로 보고 함께 바뀌게 둔다. 결과 해석에 명시한다.

## 3. 설계안

| 항목 | 값 |
|---|---|
| 수준 | 256 MiB / GC 64 (×½), 1 GiB / GC 256 (×2, 상한 600 s). 기본 512 MiB / 128은 대조군 |
| 반복 | 수준마다 n=3 |
| 대조군 | 같은 배치의 V4. revE 직후에 이어서 돌리면 revE-v4(n=3)에 V4 연결 run 1회를 더해 재사용할 수 있다. 사전 판정 기준: revE-v4 범위 ± max(3 SD, 1 %). 벗어나면 "배치 간 비교"로 낮춰 보고한다. 엄격하게 하려면 V4 n=3을 새로 돌린다 |
| 지표 | revE와 같다 (WAF, 감지·재정착·회복, 탐색 비용, 창 수, 버린 창 수) |
| seed, 부하, 러너 | revE와 같다 |

## 4. 비용

| 안 | run 수 | 예상 시간 |
|---|---|---|
| 최소 (2수준 × 3 + V4 연결 1, revE 대조군 재사용) | 7 + 단기 2 | 약 11.0 h |
| 엄격 (2수준 × 3 + V4 3, 같은 배치 무작위 블록) | 9 + 단기 2 | 약 14.0 h |
| 축소 (1 GiB만, ×2 방향) | 3 + 1 + 단기 1 | 약 6.2 h |

- revE가 11-26 04:10경 끝나므로, 승인되면 최소안은 11-26 15:20경, 엄격안은 18:20경 끝난다.
- 승컴은 같은 파라미터를 mixFYF에서 계획하지 않았다 (승컴 E4 계획은 mixR, 미실행). 중복이 아니다.

## 5. 대안 (실행하지 않을 경우)

- 논문에 "판단 구간은 경험적 설정이며 민감도는 측정하지 않았다"고 적는다.
- 기존 로그로 할 수 있는 것도 있다: 창별 WAF의 잡음 크기(창 사이 SD 5.5–7.1 %)를 보이고, 창이 작을수록 잡음이 커진다는 계산 근거를 [계산]으로 보고한다.
