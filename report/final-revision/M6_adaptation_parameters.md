## 1. 지표 정의 (사후에 바꾸지 않음)

| 지표 | 정의 |
|---|---|
| 첫 감지 | 단계 전환(B 또는 C 시작) 뒤 처음 나온 `WATGC_V2 reset`의 시각. 가장 이른 파티션 기준 |
| 복원 후보 | 리셋 직후 sample의 active에서 직전 sample의 active를 뺀 값. 단계 안에서 합산 |
| 재정착 | 파티션별 첫 리셋부터 다음 `settled`까지의 시간. 가장 늦은 파티션 값 |
| 재탐색 창 | 리셋부터 재정착까지 판단 구간 수. 파티션 합 |
| 탐색 host 비중 | 평가한 arm이 그때의 best가 아닌 구간이 처리한 host 쓰기 비중 |
| 회복 시간 | 5분 이동 WAF가 **그 run 자신의** 단계 후반 WAF × 1.05 이하로 내려와 10분 유지된 시점 |

- **회복 시간은 run 자기 자신이 기준이다.** 따라서 학습하지 않는 정책(Random)이나 리셋하지 않는 정책(V1, NoDrift)은 처음부터 정상 상태라서 짧게 나온다. **정책 간 우열 지표로 쓸 수 없다.** 같은 정책의 변화 과정을 보는 지표로만 쓴다.

**읽는 법과 해석**
1. **변화 감지는 빠르고 재현된다.** V4는 세 배치 모두 단계 C 전환 뒤 약 60 s 안에 첫 리셋을 냈다 (60.6–63.3 s).
   - 단계 B(YCSB) 전환에서는 대부분 리셋이 없었다 (revC-v4 3회 중 1회).
   - 단계 B는 WAF가 1.05 근처라서 상대 변화 25 %에 잘 걸리지 않는다.
2. **부분 리셋 대 전체 리셋 (revD).**
   - 전체 리셋은 복원 후보가 약 11배 많다 (147 대 13).
   - 재탐색 창은 3.2배, 재정착 시간은 2.4배다.
   - 탐색에 쓴 host 쓰기 비중은 0.27에서 0.56으로 늘었다.
   - 그 결과 단계 C WAF가 0.130 높다 (CI [0.052, 0.208]).
   - "변화가 생긴 파티션의 제거 후보만 되살린다"는 설계를 지지하는 측정 근거다.
3. **불리한 결과: 변화 감지를 끈 정책과 WAF가 구분되지 않는다.**
   - V1 − V4는 +0.079, NoDrift − V4는 +0.068이다. 두 배치 모두 CI가 0을 포함한다.
   - 감지를 끄면 리셋이 없어서 회복 시간 지표가 오히려 짧다 (333 대 911 s, revD). §1의 이유로 이것을 성능 우열로 해석하지 않는다.
   - 결론: mixFYF에서 변화 감지는 동작은 확인되었다 (60 s 안 감지, 부분 재탐색). 그러나 **WAF 이득은 이번 n=3에서 확인되지 않았다.**
   - 평균은 감지를 켠 쪽이 낮다 (V1 대비 −3.6 %, NoDrift 대비 −3.1 %). 그러나 감지를 끈 정책의 rep 편차가 크다 (SD 0.045–0.052).
4. **원래 iCAT**은 탐색 host 비중이 0.97이다. 리셋 뒤 재정착하지 못해 단계 C 내내 탐색했다. V4 대비 단계 C WAF +0.447의 메커니즘이다.

## 5. 논문 반영 문장 (초안)

> 단계 전환 후 iCAT-v4는 세 독립 배치에서 평균 61–63초 안에 작업 부하 변화를 감지했다. 감지 후에는 해당 파티션의 제거 후보만 복원했다(평균 13–17개). 재정착에는 340–500초가 걸렸다. 모든 후보를 복원하는 전체 리셋과 비교하면 재탐색 구간이 3.2배, 탐색 쓰기 비중이 2.1배 증가했다. 그 결과 단계 3의 WAF가 0.130 높아졌다(95% CI [0.052, 0.208], n=3). 그러나 변화 감지 기능 자체를 끈 구성과의 WAF 차이는 두 배치 모두 95% CI가 0을 포함했다. 따라서 본 작업 부하에서 변화 감지의 WAF 이득은 확인되지 않았다. 후보 제거 문턱(10–25%)과 후보 수(45 대 60)에 따른 WAF 차이도 구분되지 않았다. 판단 구간 크기, UCB 계수, 정착 조건의 민감도는 측정하지 않았다.
