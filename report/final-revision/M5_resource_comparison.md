## 1. 네 지표를 섞지 않는다

| 지표 | 무엇을 쟀나 | 단위 | 종류 | 정책 비교 가능? |
|---|---|---|---|---|
| (a) 메모리 | 학습 자료구조 크기 (gdb `sizeof` × 개수) | B | 계산 | 가능 |
| (a') 커널 메모리 | VmallocUsed 증가량 | kB | 측정, 승컴 mixY n=1 | 보조 근거만 |
| (b) 학습 경과 시간 | `learner_ns` = 판단 구간 끝의 결정 경로(observe + set_arm)를 **커널 ktime으로 잰 경과 시간** | ms | 측정 | 가능 (같은 계측이 있는 모듈끼리) |
| (b') CPU 시간 | 프로세스나 스레드 CPU 시간 | — | **미측정** | 불가. 에뮬레이터 스레드는 busy-poll이라 어떤 정책이든 CPU 하나를 약 100 % 쓴다 (schedstat) |
| (c) 지연 | FIO clat p50/p99, YCSB 평균/p99 | µs | 측정 | 가능, 단 FIO는 목표 IOPS로 고정 (§4) |
| (d) GC 수행 시간 | — | — | **미측정** | 불가. 어느 빌드에도 GC 시간 계측이 없다 |

- **선택 시간과 갱신 시간을 따로 재지 않았다.** `learner_ns`는 보상 갱신, 제거, 정착, 변화 감지, 다음 arm 선택을 한 구간으로 잰다.
- GC마다 호출되는 구간 누적 훅도 `learner_ns`에 들어 있지 않다.

## 3. 학습 경과 시간 [측정, ktime, CPU 시간 아님]

고컴 revA mixFYF 90분, 4 파티션 합, n=3.

| 정책 | 결정 경로 누적 경과 시간 | 1회 평균 | 측정 구간 5,404 s 대비 |
|---|---|---|---|
| iCAT-v4 | **3.88 ms** (3.865 / 3.781 / 3.993) | 3.92 µs | 0.00007 % |
| V1 (변화 감지 없음) | 3.68 ms | 3.68 µs | 0.00007 % |
| V2 (제거·정착 없음) | 9.04 ms | 9.78 µs | 0.00017 % |
| Random Selection | 2.77 ms | 3.03 µs | 0.00005 % |

- 제거를 끄면 1회 비용이 약 2.5배가 된다. 매 구간 모든 활성 후보의 UCB를 계산하기 때문이다.
- GC마다 도는 훅을 포함한 비용은 미측정이다.
  - [추정] 승컴 resource-v124 계측(FIO-Fast)의 GC당 차분 9.4 ns를 빌리면 90분에 약 47 ms다. 그래도 0.001 % 수준이다.
  - 논문에는 측정값을 먼저 쓰고, 추정값은 추정이라고 밝힌다.
- 원 논문식 표현을 쓰지 않는다: "CPU 사용률 x %"라고 쓰지 않는다. "결정 경로 경과 시간(커널 ktime)"이라고 쓴다.

- **FIO p99는 iCAT-v4가 Random보다 높았다** (단계 C에서 +15–20 µs, CI가 0을 포함하지 않음). WAF는 V4가 Random보다 8.4 % 낮다.
  - 낮은 WAF가 더 낮은 꼬리 지연으로 이어지지 않았다.
  - 원인은 확인하지 않았다. 고른 arm의 희생 블록 선택 방식이 지연 분포에 영향을 준다는 것은 가설이다.
  - 승컴 revD에서도 같은 방향이었다 (V4 147 대 NoDrift 134 µs, 승컴 `evidence-by-review.md` §2).
- p50과 YCSB 지연은 차이가 없거나 1 µs 이내다.
- 처리량은 FIO가 고정이라 비교할 수 없다. YCSB 처리량은 V4가 1.0 % 높다.
- 해석 범위:
  - erase 지연이 0인 에뮬레이터라 GC 시간이 지연에 거의 반영되지 않는다 (M7).
  - 이 지연 결과는 실제 SSD로 옮길 수 없다.

## 6. 논문 반영 문장 (M5 답변 초안)

> 학습 상태는 4개 파티션 합계 10,112 B이며 장치 용량과 무관하다(구조체 크기 계산). 판단 구간마다 실행되는 학습 결정 경로의 경과 시간을 커널 ktime으로 쟀다. mixFYF 90분 동안 합계 3.88 ms(1회 평균 3.9 µs, 3회 반복)였고, 측정 구간의 0.0001 % 미만이다. 이 값은 CPU 사용 시간이 아니라 경과 시간이다. GC마다 실행되는 구간 누적 코드는 포함하지 않았다. 에뮬레이터 스레드가 busy-poll 구조여서 정책별 CPU 사용률은 구분할 수 없었다. GC 수행 시간은 계측하지 않았다. 지연 측면에서 YCSB 지연과 FIO p50은 무작위 선택과 차이가 없었다. 반면 FIO p99는 iCAT-v4가 15–20 µs 높았다(단계 3, 95% CI가 0을 포함하지 않음). 따라서 WAF 감소가 꼬리 지연 개선으로 이어진다고 주장하지 않는다.

## 7. 검증할 수 없는 항목

| 항목 | 이유 | 필요한 것 |
|---|---|---|
| CPU 시간 (프로세스, 스레드) | busy-poll, 계측 없음 | 학습 코드에 `task_cputime` 계측 또는 perf 샘플링 |
| GC 수행 시간 | 계측 없음, erase 지연 0 | GC 경로 ktime 계측 빌드 |
| 선택과 갱신 시간 분리 | 한 구간으로 측정 | 계측 지점 분리 |
| SmartGC 학습 비용 | 계측 없음 | 계측 빌드 |
