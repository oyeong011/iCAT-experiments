## 2. E3 적응 속도 (사전 등록 지표 3–6, 파티션 단위) [측정]
`e3_partition.csv`, `e3_run.csv`, `e3_stats.csv`의 값이다. 표 안의 숫자는 정책별 3개 run의 값이다.

| 호스트 | 정책 | 단계 C 첫 감지 (s) | 리셋한 파티션 수 | 재탐색 창 수 합 (지표 5) | 가장 늦은 재정착 (s) | 회복 시간, 사전 정의 (s) |
|---|---|---|---|---|---|---|
| 승컴 | V4 | 74 / 43 / 69 | 3 / 2 / 4 | 100 / 32 / 69 | 915 / 279 / 305 | 801 / 1011 / 920 |
| 승컴 | FullReset | 65 / 67 / 12 | 3 / 4 / 3 | 202 / 258 / 184 | 1239 / 1144 / 1163 | 1107 / 1080 / 1014 |
| 승컴 | NoDrift | 해당 없음 (설계상 리셋 없음) | 0 | – | – | 315 / 322 / 362 |
| 고컴 | V4 (revA) | 63 / 66 / 62 | 4 / 4 / 3 | 74 / 74 / 54 | 357 / 403 / 321 | 396 / 756 / 756 |
| 고컴 | V1 = NoDrift | 해당 없음 | 0 | – | – | 307 / 306 / 605 |

- **감지 시점:** V4는 두 호스트 모두 단계 C 시작 뒤 약 1분(43–74 s)에 첫 리셋을 했다. 판단 구간 3개가 연속으로 25 %를 넘을 때 리셋하는 설계와 맞는다.
- **재탐색 시작:** 리셋하는 즉시 재탐색을 시작한다. 그래서 시점은 감지 시점과 같다.
- **재정착:**
  - V4 파티션별 재정착은 233–914 s다. 9개 파티션 중 8개가 400 s 이내에 재정착했다.
  - FullReset은 911–1239 s다. 후보 45개를 다시 순회하므로 재탐색 창 수가 약 3배다.
  - 두 정책의 CI는 겹친다. 이 차이는 기술 통계로만 보고한다.
- **회복 시간 해석 주의:** 기준값이 "자기 run 단계 후반 WAF"다. 그래서 단계 C 내내 WAF가 높게 평평한 정책은 최소값(약 300 s)에 가깝게 나온다. NoDrift의 333 s는 빨리 회복했다는 뜻이 아니다. 비교 지표로 쓰지 말고, 단계 C WAF와 함께만 보고한다.
- **결론:** 감지와 재정착의 시점과 비용은 측정했다. "V4가 더 빨리 적응한다"는 통계적으로 입증하지 못했다.

## 3. 할인 계수 γ [계산]
- **설정값:**
  - γ = 65503/65536 = 0.999496
  - 매 창마다 45개 arm 통계 전부에 곱한다
  - 반감기 1376창, 유효 기억 길이 1/(1−γ) ≈ 1986창
- **실제 창 수:** 90분 run 한 번에 파티션당 228–255창이다 (`gamma.csv`). 단계별로는 A 약 110, B 약 10, C 110–129창이다.
- **실제 가중치:**

| 경우 | 가장 오래된 창의 가중치 (run 끝 시점) |
|---|---|
| 리셋 없음 (NoDrift, V1, Random) | 0.879–0.892 |
| 리셋 있음 (V4, FullReset; 마지막 리셋 이후) | 0.936–0.947 |
| 단계 A 끝 데이터 (run 끝 시점) | 0.930–0.942 |

- **해석:** 실험 기간 안에서 할인이 옛 데이터를 줄이는 폭은 최대 약 12 %다. 단계 전환 적응은 할인이 아니라 리셋이 맡는다.
- **한계:** γ = 1 run이 없다. 그래서 "할인을 빼도 WAF가 같다"는 측정하지 않았다. 위 결과는 계산이다.

## 4. E5 지연 시간 [측정, 기술 통계만]
`latency_stats.csv`의 정책별 평균이다. 모두 NVMeVirt 시간 모델 기준이다.

| 호스트 | 정책 | FIO C hot p50 (µs) | FIO C hot p99 (µs) | FIO C cold p99 (µs) | YCSB READ 평균 / p99 (µs) | YCSB UPDATE 평균 / p99 (µs) |
|---|---|---|---|---|---|---|
| 승컴 | V4 | 10.30 | 147.1 | 164.9 | 15.50 / 85.7 | 13.26 / 83.0 |
| 승컴 | NoDrift | 10.26 | 133.5 | 149.8 | 15.90 / 85.3 | 13.46 / 83.0 |
| 승컴 | FullReset | 10.26 | 145.1 | 159.4 | 16.06 / 86.0 | 13.55 / 83.7 |
| 고컴 | V4 | 11.58 | 122.0 | 128.7 | 11.70 / 79.0 | 10.55 / 78.0 |
| 고컴 | V1 | 11.46 | 117.2 | 126.8 | 11.73 / 79.7 | 10.56 / 78.7 |

- **p50:** 정책 사이 차이는 1 % 안팎이다. YCSB 평균과 p99도 정책 사이 차이가 0.1–0.6 µs 안팎이다.
- **⚠️ FIO p99:** 두 호스트 모두 V4가 비교 정책보다 높다.
  - 승컴: V4 147 vs NoDrift 134
  - 고컴: V4 122 vs Random 103
  - 검정은 하지 않았다. "학습이 I/O 지연을 늘리지 않는다"는 주장은 이 데이터로 할 수 없다. 오히려 꼬리 지연 증가 가능성을 한계로 적어야 한다.
- 학습 CPU 시간은 이미 push한 `stats.csv`의 C_learner_ms다 (승컴 V4 1.32 ms / 단계 C 30분).

## 5. Random Search 기댓값 (고컴 데이터만)

| 구분 | 내용 | 전체 WAF |
|---|---|---|
| [측정] n=3 | V4 (revA) | 2.128 (2.123 / 2.131 / 2.132) |
| [측정] n=3 | V1 = NoDrift (revA) | 2.207 |
| [측정] n=3 | V2 (revA) | 2.264 |
| [측정] n=3 | Random Selection (revA) | 2.324 (2.327 / 2.329 / 2.318) |
| [측정] **n=1** | arm 47 고정 | **1.987** |
| [보정] | arm47 추정 − 측정 | +0.085 (단계 A +0.148, C +0.021) |
| [추정] | Random Search k = 1 / 5 / 12 / 45 (1창씩 시험 후 고정) | 2.306 / 2.263 / 2.253 / 2.214 |
| [추정] | 사후 최적 단일 arm (arm 46) | 2.046 |

- 추정기는 arm47에서 약 +0.085 높게 나왔다. 같은 오차를 빼면 Random Search 기댓값은 약 2.13–2.22다.
- 이 범위는 V4 측정값 2.128과 겹친다. 따라서 **"V4가 Random Search보다 낫다"는 입증되지 않았다.** "Random Selection보다 낫다"(+0.196, 측정, n=3)만 입증된 것이다.
- **⚠️ 위험:** 고정 arm 47(n=1, 1.987)이 V4보다 낮다.
  - 심사위원이 "최적 고정 arm보다 나쁘다"고 지적할 수 있다.
  - 답변의 핵심은 사전 지식 없이 고정 arm을 고를 수 없다는 점이다. Random Search 추정치가 그 비용을 보여준다.
  - arm47 n=3이 없으므로 수치 비교는 n=1이라고 명시해야 한다.
