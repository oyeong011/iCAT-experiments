## 4. 4.1절 예외 4종: 원시 근거와 가능한 해석

원자료는 `tables/sec41_exceptions.csv`다. `analysis/summary.py`의 집계를 그대로 다시 실행했고 run별 값을 포함한다.

| 예외 | 원시 값 (run별) | 사실 (계산값) |
|---|---|---|
| **Varmail 단독: iCAT > Greedy** | iCAT 4.935, 4.930, 4.916 (n=3, SD 0.010). Greedy 4.762 (n=1). 최악 CAT(arm 10) 4.970, CAT-Default 4.623 (n=3), CAT-Best 3.537 | iCAT은 Greedy보다 +3.5 %, 최악 CAT보다 −0.9 %. iCAT의 호스트 쓰기는 19.1–19.5 M 페이지, Greedy는 20.4 M(5분 시간 기준 실행) |
| **YCSB-B(SQLite 95/5) 단독: iCAT < Default** | iCAT 1.105, 1.106, 1.102. Default 1.113, 1.112, 1.114 (각 n=3) | 차이 −0.8 %. 3회 범위가 겹치지 않는다(1.102–1.106 대 1.112–1.114) |
| **OLTP → Varmail 1배: iCAT < Default** | 전체: iCAT 1.915, 1.957, 1.966 대 Default 2.304, 2.322, 2.350 | 전체 −16.3 %. **단계별로 방향이 반대다:** OLTP 단계 iCAT 1.598 > Default 1.417, Varmail 단계 iCAT 2.005 < Default 2.497 |
| **YCSB-A → OLTP 1배: iCAT < Default** | 전체: iCAT 1.166, 1.169, 1.178 대 Default 1.229, 1.224, 1.240 | 전체 −4.9 %. 단계 A(YCSB-A)에서 1.387 < 1.406, 단계 B(OLTP)에서 1.153 < 1.217 |

**가능한 해석** (가설이며 고컴은 검증하지 않았다):
- **H1 — CAT-Default(arm 37)는 Varmail과 OLTP 계열에 특히 맞지 않는다.**
  - 근거(계산값): Varmail 단독에서 Default는 CAT-Best보다 +30.7 %다. OLTP → Varmail의 Varmail 단계에서 Default 2.497은 CAT-Best 1.943보다 +28.5 %다.
  - 이런 경우 여러 조합을 섞어 쓰는 iCAT의 평균이 arm 37 하나보다 낮을 수 있다.
  - 확인하려면 iCAT의 판단 구간별 조합 기록(커널 로그)이 필요하다. 1배 run의 로그로 확인할 수 있는지는 확인하지 않았다.
- **H2 — 5분 Varmail 단독에서 iCAT은 초기 순회(약 30분) 중에 실행이 끝난다.** 따라서 사실상 순회 순서상 앞쪽 조합들로 돌아간다. iCAT 값이 최악 CAT(4.970)에 가깝다는 점과 맞는다. 순회 순서는 확인하지 않았다.
- **H3 — Varmail은 5분 시간 기준이라 정책마다 호스트 쓰기량이 다르다**(19.1–20.4 M). 같은 쓰기량의 비교가 아니다. Greedy가 n=1이라 반복 간 차이를 모른다.
- **H4 — YCSB-B 차이(−0.8 %)는 작지만 3회 범위가 겹치지 않는다.** "Default < iCAT"가 일반 규칙이 아니라는 근거로 충분하다. 크기는 실용적으로 작다.

**원고 처리 선택지 (저자 결정):**
- (a) 지금처럼 "17종 중 13종, 예외 4종"으로 사실만 쓴다(현재 적용).
- (b) H1을 한 문장으로 덧붙인다("CAT-Default가 Varmail 계열에 부적합해…"). H1의 수치 근거는 위 표에 있다.
- (c) 4.1절 결론을 "iCAT은 대부분의 경우 CAT-Default보다 높다"로 완화한다. 요약과 결론에도 반영해야 한다.
