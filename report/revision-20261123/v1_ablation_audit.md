# V1 Ablation 점검: V1은 "변화 감지·재탐색 제거" 버전이 아니다

작성: 2026-11-23 (승컴). 근거 commit `1d98bb881`. 이 문서는 버전 이름이 아니라 소스 코드로 확인한 내용이다.

## 1. 코드로 본 V1, V2, V4의 실제 차이

| 기능 | V1 `online-mix-src` | V2 `online-v2-src` | V4 `online-v4-src` |
|---|---|---|---|
| 후보 수 | 60 (`conv_ftl.h:32`) | 60 | 45, k=2 제외 (`conv_ftl.h:33`, `conv_ftl.c:140`) |
| 판단 구간 | 64 GC + 256 MiB (`conv_ftl.h:41`) | 192 GC + 768 MiB | 128 GC + 512 MiB (`conv_ftl.h:43–44`) |
| 초기 순회 | 조합당 3회 (`MIN_VISITS 3`, h:50) | 1회 | 1회 (h:52) |
| **변화 감지 (drift)** | **있음**, 12.5 %, 3구간 연속 (h:56–57, c:484–495) | 있음, 12.5 % | 있음, 25 %, 3구간 연속 (h:58–59, c:534–545) |
| **감지 후 재탐색** | **있음**, 60개 통계 전부 초기화 후 재순회 (c:400–420) | 있음, 같음 | 있음, 남은 후보와 1칸 이웃만 복원 (c:448–470) |
| 오래된 조합 재방문 | 240구간 (h:55, c:372) | 같음 | 같음 (h:57, c:414–416) |
| 정착 후 탐색 | 8구간마다 가장 오래된 조합 (c:540–545) | 같음 | 8구간마다 1등의 1칸 이웃 (h:56, c:606–618) |
| 실행 중 후보 제거 | 없음 | 없음 | 15 % (h:34, c:581–598) |

**결론:** V1에도 변화 감지와 재탐색이 들어 있다. 그래서 V1 대 V4 비교로는 "변화 감지·재탐색 기능의 효과"를 보일 수 없다. 두 버전은 후보 수, 판단 구간, 순회 횟수, 정착 후 탐색, 후보 제거, 재탐색 범위의 여섯 가지가 동시에 다르다.

같은 지적은 11-14 자원 실험의 `result/resource-v124-20261114/report/implementation_audit.md`에도 있다 (branch `resource-overhead-20261114`).

## 3. 변화 감지·재탐색 효과만 분리하려면

- 지금 빌드되어 있는 제거 실험용 모듈은 세 가지다. 모두 9월에 queue32로 사전 등록했지만(`EXPERIMENT_LOG.md:10611`) 실행된 적이 없다. main, origin/icat-2, 결과 폴더 어디에도 결과가 없다.
  - `nvmev-online-v4noelim.ko` (`d4e5750e…`): 후보 제거를 끔 (h:34의 값을 무한대로)
  - `nvmev-online-v4noprobe.ko` (`52071ff4…`): 이웃 탐색을 끔 (h:56 = 0)
  - `nvmev-online-v4fullreset.ko` (`9b4ac457…`): 재탐색 때 45개를 전부 복원 (c:459)
- **변화 감지 자체를 끈 빌드("v4nodrift")는 없다.** DRIFT_WINDOWS를 사실상 무한으로 바꾸는 한 줄 변경이며, 기존 알고리즘 코드는 건드리지 않고 새 빌드로만 만든다.
- 실험 계획은 `additional_experiment_plan.md`의 E1에 있다.
